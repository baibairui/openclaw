# Skill Reflection / Writeback

适用场景：

- 同类任务反复失败，且失败不像是偶发执行问题
- 现有 skill 说明不够清楚，导致选路或执行重复出错
- 已有经验足够稳定，值得升级成 skill 级做法

默认流程：

1. 先判断是“缺能力”还是“skill 不够好”
2. 如果是 skill 问题，记录：
   - 受影响的 skill
   - 失败模式
   - 证据
   - 建议改法
3. 先写 skill-writeback 候选
4. 不直接覆盖正式 skill，等待后续验证

候选至少要有：

- `skill`
- `issue`
- `evidence`
- `proposal`
- `why_now`

保守原则：

- 一次偶发失败，不升级成 skill-writeback
- 没有证据，不做 skill 级修改建议
- 先生成候选，再判断要不要正式改技能
