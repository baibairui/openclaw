# 用 cron 驱动梦境思考

梦境思考适合被 OpenClaw 的 `cron` 调度，而不是在用户当前对话里硬触发。

## 推荐调度方式

- 运行在 `isolated` session
- 使用 `--message` 触发一次 agentTurn
- 默认 `--light-context`
- 默认 `--no-deliver`

这样做的目标是：

- 不打断用户当前会话
- 不把梦境结果主动推送给用户
- 把结果安静写入 `memory/dreams/`

## 推荐消息模板

调度消息应该明确要求：

- 进入 dream-cycle
- 只整理和生成候选
- 不直接修改正式规则
- 不执行外部动作
- 输出到小龙虾工作区的梦境目录

## 适合的频率

- 每日一次：长期陪跑型小龙虾的默认值
- 每周一次：如果任务密度低，优先保守
- 不建议高频到每小时，容易制造噪音

## 什么时候不要调度

- 当前 runtime 还没稳定
- 工作区没有足够的近期高信号痕迹
- 用户明确不希望后台整理
- 还没区分清楚 dream 候选和正式记忆吸收流程
